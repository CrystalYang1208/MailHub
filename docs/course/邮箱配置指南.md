# 测试邮箱与授权配置

无需主力真实邮箱。推荐新建专用QQ/163测试邮箱，避免真实隐私邮件进入课程演示。授权码、密码、Google客户端JSON只在你本机填写，禁止发给助手、同学、截图或Git仓库。不要把`.local`目录打包交作业。

## QQ 与163 /126

1. 登录服务商官网，在账号设置中打开IMAP/SMTP。QQ通常位于“设置 → 账号 → POP3/IMAP/SMTP服务”；163/126位于“设置 → POP3/SMTP/IMAP”。页面位置可能随服务商调整。
2. 按服务商安全验证生成“客户端授权码/客户端授权密码”，不要使用网页登录密码。
3. 运行正式版，创建本地用户，添加邮箱并选择模板，填完整地址与授权码，点击“校验并连接”。系统会验证收件和发件服务。

| 模板 | IMAP | SMTP | 安全方式 |
|---|---|---|---|
| QQ | imap.qq.com:993 | smtp.qq.com:465 | 隐式TLS |
| 163 | imap.163.com:993 | smtp.163.com:465 | 隐式TLS |
| 126 | imap.126.com:993 | smtp.126.com:465 | 隐式TLS |
| Gmail | imap.gmail.com:993 | smtp.gmail.com:587 | IMAP TLS / SMTP STARTTLS |
| Outlook | outlook.office365.com:993 | smtp-mail.outlook.com:587 | IMAP TLS / SMTP STARTTLS |

首次同步范围固定为最近90天；正文索引逐渐完成，界面会提示搜索覆盖率。阅读缓存只对已经缓存的正文提供离线阅读，不承诺断网读取未缓存的正文。

## Gmail OAuth

1. 在你自己的Google Cloud项目中配置OAuth同意屏幕，选择适用的测试发布状态，将专用测试邮箱添加为测试用户。具体流程以Google当时控制台为准。
2. 创建类型为“桌面应用”的OAuth客户端，下载JSON。项目需要IMAP/SMTP使用的`https://mail.google.com/`邮件scope；生产公开分发资格不等于课程测试用户授权。
3. 正式版“设置与隐私 → Google授权配置”导入原始JSON。应用只使用固定Google授权和token端点，不接受自定义跳转端点。
4. 添加Gmail，填地址，选择OAuth，在浏览器中授权Google。完成后回到工作台点击连接。浏览器只收到flowId，不持有access/refresh token。
5. 授权撤销后可重新授权；网络失败会重试。Google测试状态的有效期、限制与审查规则以其官方政策为准。

如果测试邮箱具备应用专用密码资格，也可开启两步验证后使用应用专用密码。不是所有Google账号都可生成，不使用普通账号密码替代OAuth。

## Outlook与学校邮箱

Outlook模板只预填标准服务器，复用通用协议，**未实现Microsoft OAuth**。Microsoft已对多数个人账号停用基本认证，因此可能被策略拒绝；只有仍明确允许相应认证的账号/组织环境可用。课程演示不要把五种模板齐全解释为五家服务商均已真实登录通过。

学校邮箱可选“其他IMAP邮箱”并手填参数。严格校验证书；使用私有CA时按学校合法系统信任策略部署证书，应用不提供关闭TLS校验的开关。

## 发送与异常

专用收件账号用于观察实际到达。界面“已提交邮件服务器”只表示SMTP接受，不代表对方收到。若显示“结果未知”，先去服务商已发送和受控收件端核对；确认可能重复后才允许返回编辑并手动重发。演示模式可用主题`[失败]`或`[未知]`测试这两条路径，正式模式不把主题当故障开关。

## 常见问题

- 授权失败：检查授权码、IMAP开关与账号策略；服务商响应不明确时应用不会假装能准确判定原因。连续三次失败冷却十分钟。
- 服务器地址/端口错误：检查模板是否选错、是否要求STARTTLS；不关闭证书验证来绕过错误。
- 本地启动链接失效：再次运行启动器取得新链接。令牌只在浏览器内存，直接刷新旧链接不可重新使用已消费的引导码。
- 忘记本地密码：没有绕过认证的找回接口。先保留数据与备份，不要随意删除数据库；凭据需原Windows身份和本地密码解封。
- 测完后：在官网撤销测试授权码/令牌；移除账号会清除该账号的本机缓存，服务端邮件仍保留。用户主动下载的附件由用户自行管理。
