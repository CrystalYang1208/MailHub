# 建议8分钟答辩演示

## 0:00–1:00：需求与边界

痛点：QQ/163/Gmail等邮箱分散，需要统一查看、搜索和回复。形态：本地桥接程序＋浏览器，数据不经运营方云端。有效范围35FR：24Must、11Should；五种参数模板；最多四个本地用户，单一活跃身份。

展示原Word与Starter范围差异及用户确认记录。说明会话合并、高亮、自启、迁移等已取消项，避免把未做项包装为已做。

## 1:00–2:00：OpenSpec实际使用

打开`openspec/changes/deliver-mailhub-course-project`的proposal、specs、design和tasks。终端运行：

```powershell
npx openspec --version
npx openspec status --change deliver-mailhub-course-project --json
npx openspec validate --all --strict --no-interactive
```

说明需求行为、技术方案、实施任务和测试证据的区别。外部真实验收任务仍未勾选，不能用规范校验通过代替产品验收。

## 2:00–4:00：前后端闭环

运行`运行演示.cmd`，点击进入演示工作台：

1. 三个合成邮箱在统一收件箱混排，每封带来源；展开一个账号看文件夹。
2. 打开邮件，展示安全格式化/纯文本正文与附件下载。说明正文读取不自动改已读，按钮操作需服务器确认。
3. 搜索“实习证明”，筛选账号/时间/未读/附件；展示索引覆盖状态和本地SQLite数据。
4. 三步添加126合成账号，展示模板参数与本地凭据保护边界。演示模式只接受example.invalid。

## 4:00–5:30：发送、失败与恢复

回复一封邮件，展示原文引用与后端线程头来源。收件人填`receiver@example.invalid`：

- 普通主题：合成提交成功；强调不等于实际投递。
- 主题含`[失败]`：失败保留草稿；关闭再从草稿箱恢复。
- 主题含`[未知]`：结果待核对，不自动重发；显示显式确认可能重复的入口。

这些故障开关只存在于合成适配器，正式MailKit适配器不会按主题伪造失败或成功。

## 5:30–6:30：用户隔离与存储

左下角锁定/切换身份，创建第二用户，说明四用户槽位、旧令牌失效与独立用户库。设置中展示缓存限额及索引独立保留。邮件正文与索引属于本机敏感数据；凭据加密不等于所有邮件文件都加密。

## 6:30–8:00：验证与诚实结论

展示验收记录：后端26项、前端单元3项、浏览器合成7项、OpenSpec10项严格校验；以最终验收记录中的实际结果为准。展示1000封本地搜索三次计时。

若你已完成本机真实测试，再演示QQ/163测试邮箱与受控收件端的实际收发；未完成就明确写NOT_TESTED或BLOCKED。Win11/DPAPI、Chrome/Edge以及Gmail OAuth需真实外部验收。Outlook只有参数模板，未实现Microsoft OAuth。

最后说明架构上最关键的三个取舍：本地隐私边界；UID代次与事务检查点；发送未知状态避免重复。报告中不写“所有Must已通过正式验收”，直到本机结果具备依据。
