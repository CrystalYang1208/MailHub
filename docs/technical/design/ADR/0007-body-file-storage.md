# ADR 0007 正文缓存与附件存储

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
原型曾出现已提交510MB窗口；索引必须独立保留；附件需本地文件系统。

## 问题
阅读缓存配额与DB/WAL物理空间不同，文件和SQL不能共同事务。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 提交正文再异步LRU | 实现简单 | 有可见/持久超限，已被原型反证 |
| 同事务预淘汰+写入+配额账本CHECK | 读者看不到超限提交 | 需要单写队列，降低配额也需淘汰 |
| 正文也存外部文件 | 可流式大对象 | 配额/读取租约及崩溃文件补偿更复杂 |

## 最终推荐决策
阅读正文存MessageBody UTF8 Blob；先同事务LRU预淘汰再写，CacheQuota CHECK硬守卫。附件/草稿文件用FileObject staging/ready/cleanup协议，不占阅读500MB；SearchDocument独立。

## 决策理由
采纳ADR0003修正方向且便于数据库事务保证，不引入未经需求要求的对象存储。

## 代价与风险
DB/WAL与索引实际空间可能超过500MB；附件不自动永久删除用户已导出文件，SSD不保证安全擦除。
