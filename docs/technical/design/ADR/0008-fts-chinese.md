# ADR 0008 FTS5中文搜索策略

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
FTS5跨账号合成1000封通过，trigram无法MATCH短于3字符的词。

## 问题
不能把未索引正文当零命中，也不能以SQLite NOCASE冒充完整Unicode大小写处理。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 仅unicode61 | 低成本 | 中文未按词划分，短词覆盖差 |
| trigram+安全phrase+1/2字符LIKE回退 | 沿用已验证SQLite方案，可同事务维护 | 短词扫描有成本，需规范化与查询预算 |
| 引入Lucene/外部中文分词服务 | 更丰富排序/词法 | 新依赖/索引一致性与路线改变，当前无必要 |

## 最终推荐决策
FTS5 external-content SearchDocument、trigram，输入和索引NFC/casefold；长词引用phrase，1～2码点参数化LIKE ESCAPE，反馈coverage和可取消预算。阅读缓存淘汰不删索引。

## 决策理由
保持SQLite选型，修补已知短词限制，不用合成性能承诺任意库一秒。

## 代价与风险
LIKE ESCAPE不能依赖trigram索引优化，大库短词可能超预算；正文索引增长是明确代价。

## 后续验证与设计合同
产品实际1000封基准、中文混合大小写/通配符字面语义、取消、索引重建与覆盖。
完整实施合同：[设计文档](../SEARCH_STORAGE_DESIGN.md)。后续验证为产品/工程阶段计划，不表示本阶段已执行或重启阶段二。
