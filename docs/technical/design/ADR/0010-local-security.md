# ADR 0010 前后端本地通信与邮件安全

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
真实Chrome/Edge最小安全主流程通过，运营方服务器被排除。

## 问题
localhost可能被恶意网页访问，邮件HTML不可信；进程token不能代替用户认证。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 只监听回环 | 简单 | 仍可被恶意网页盲请求 |
| 同源+随机BridgeToken+用户session+Host/Origin | 可逐层授权并拒绝跨站 | 多标签页引导、会话切换需管理 |
| 跨源开发服务器+通配CORS | 开发方便 | 扩大浏览器攻击面，不采用生产配置 |

## 最终推荐决策
采用同源127.0.0.1、一次性fragment引导、内存BridgeToken及用户session双校验、严格Host/Origin/Fetch Metadata，禁止通配CORS。邮件清洗后隔离sandbox空权限+CSP禁止资源，邮件内iframe移除。

## 决策理由
沿用已验证原型且覆盖明确安全威胁，浏览器无需任何邮箱凭据。

## 代价与风险
富HTML兼容受保守白名单限制；不是防同Windows恶意进程/管理员的隔离。

## 后续验证与设计合同
产品登录切换/旧下载、真实邮件复杂格式与浏览器回归，不开展无关完整渗透。
