# ADR 0005 数据库及多用户隔离

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
最多4个应用用户共用同Windows身份，需要账号、FTS、缓存和草稿全部隔离。

## 问题
共享库漏owner过滤以及跨库唯一账号与原子性的矛盾。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 共享SQLite加owner字段 | 跨用户统计方便 | 每个FTS/附件请求都可能漏过滤 |
| 每用户SQLite加小目录库 | 连接级隔离，查询自然仅属当前用户 | 需目录预留和幂等跨库补偿 |
| 每用户Windows账户或独立数据库服务 | 操作系统或服务隔离 | 不符合当前应用用户形态或部署成本 |

## 最终推荐决策
每用户Profile库+catalog身份/封套/AccountReservation；当前会话选择固定库。地址HMAC唯一预留覆盖本安装四用户，跨库采用CatalogOperation补偿，不声称WAL ATTACH全局事务。

## 决策理由
隔离范围清楚、开发人员不需每次跨库过滤，SQLite路线保持。

## 代价与风险
多个物理库需分别迁移和一致备份；不承诺对同Windows恶意进程的明文邮件静态保密。

## 后续验证与设计合同
四用户产品API/文件/事件隔离及跨库注册删除中断恢复。
完整实施合同：[设计文档](../DATABASE_DESIGN.md)。后续验证为产品/工程阶段计划，不表示本阶段已执行或重启阶段二。
