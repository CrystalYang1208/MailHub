# ADR 0006 用户密码与密钥管理

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
DPAPI CurrentUser不能隔离同Windows下的A/B应用用户，M3已证明额外密码层可行。

## 问题
不能只加登录UI或依赖DPAPI；需要改密码可原子完成而不重加密每封凭据。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 仅密码验证+DPAPI | 简单且原生 | 共享Windows身份能解DPAPI，凭据无密码层 |
| 密码直接加密所有凭据 | 应用密码层隔离 | 改密需批量重写、失败复杂 |
| 随机UMK+密码KEK封套+DPAPI | 改密只换封套，用户/账号AAD边界明确 | 丢密码不可恢复，密钥生命周期需严格实现 |

## 最终推荐决策
采用随机用户UMK、独立盐PBKDF2-SHA256>=600000的验证值与KEK，AES-GCM封套外加DPAPI；凭据AES-GCM绑定用户/账号后再次DPAPI。改密在catalog同事务更新验证/封套/authVersion，退出清密钥。

## 决策理由
延续密码+DPAPI决策，不加整库加密或第三方密码体系；使用.NET现有算法，明确同Windows边界。

## 代价与风险
KDF需要阶段四校准；不能保证托管字符串绝无残留；没有无损忘记密码找回。

## 后续验证与设计合同
持久封套重启、改密崩溃、AAD交换、刷新并发、四用户/旧会话与日志哨兵。
