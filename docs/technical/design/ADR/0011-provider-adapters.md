# ADR 0011 邮箱服务商适配架构

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
163真实读取曾因缺ID失败并修正；Gmail代理路径与OAuth有特殊性。

## 问题
厂商判断散落会导致业务层与协议/凭据耦合。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 每模块直接MailKit及厂商if | 初期快 | 重复认证/错误策略、难测试 |
| ProviderRegistry+能力端口+会话工厂 | 特殊规则集中且通用邮箱仍可配置 | 需有限接口和能力矩阵 |
| 每服务商独立微服务 | 完全隔离 | 本地部署过重，不符合产品 |

## 最终推荐决策
模板是配置默认值，特例在ProviderProfile/适配器；163 ID、Gmail XOAUTH2/刷新、特殊文件夹、错误映射与ConnectionPolicy集中实现。一个Client串行；安全TLS、超时/取消一致，业务只消费能力。

## 决策理由
不推翻MailKit/MimeKit，保留generic IMAP/SMTP，不被三个品牌枚举锁死。

## 代价与风险
不能从所有失败精确推断IMAP未开；能力不足需明确失败，绝不降级永久删除或明文连接。

## 后续验证与设计合同
Gmail应用专用密码资格/公开分发、无MOVE服务器安全降级、学校自签CA合法部署与特殊Folder。
完整实施合同：[设计文档](../EMAIL_INTEGRATION_DESIGN.md)。后续验证为产品/工程阶段计划，不表示本阶段已执行或重启阶段二。
