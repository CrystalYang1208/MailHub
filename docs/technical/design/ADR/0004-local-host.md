# ADR 0004 本地后台架构

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
Windows本地协议、浏览器UI、DPAPI及无运营方服务器已确定，需要长期任务与明确退出语义。

## 问题
避免Windows Service身份错配、浏览器标签退出影响后台及业务/协议耦合。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| Windows Service | 长期驻留 | 管理员安装、DPAPI与交互身份管理复杂 |
| 用户级单宿主托盘+同源Kestrel | 当前Windows身份直接保护、单进程易维护 | 浏览器关闭不等于退出，需租约/锁定状态 |
| Electron/云端桥接 | 统一壳或部署集中 | 改变已定形态或隐私边界，不采用 |

## 最终推荐决策
沿用.NET10用户级单宿主、127.0.0.1动态Kestrel同源托管Vue。模块化分层，单实例，命名管道仅协调打开工作台。锁定/切换暂停该用户任务；关闭标签不暂停，正常退出持久保存状态。

## 决策理由
满足已接受D1及本地化边界，避免为小型本地系统引入微服务或服务账户。

## 代价与风险
宿主故障影响所有本地模块，需恢复记录；只有解锁用户可同步，不提供锁定用户无密码后台解密。
