# ADR 0009 同步事务及重试

状态：阶段三设计决策，待本阶段整体审核；已接受技术栈/密码/平台约束保持不变。日期：2026-11-15。先前ADR0001～0003保留在上级ADR目录，不覆盖历史。

## 背景
已验证UID核心算法、真实20-UID网络中断恢复与独立任务持久化。

## 问题
产品还需固定扫描边界、FLAGS/删除对账、epoch守卫，不能直接照搬原型长网络事务。

## 候选比较

| 方案 | 优点 | 缺点与适用性 |
|---|---|---|
| 仅记最后返回UID | 简单 | 部分FETCH/稀疏UID可能遗漏，无法对账删除 |
| 固定UID范围+原子批次+持久任务 | 游标/头/索引同提交、可恢复 | 需状态与扫描辅助表 |
| 网络和SQL放同一长事务 | 写法直观 | 锁跨网络等待，阻塞单写队列 |

## 最终推荐决策
网络在事务外；短事务检查用户/账号/文件夹epoch及任务lease，提交头/SearchDocument/检查点/进度。初次固定90天，代次变化按原需求全量重建。retry持久，1/2/4/8分钟，可控时钟测试；3/5上限。

## 决策理由
直接处理阶段二已见风险而不夸大其验证范围，可并行模块开发。

## 代价与风险
远程服务器与本地非分布式事务；用幂等/状态对账而非exactly-once承诺。

## 后续验证与设计合同
产品多Folder/多账号、FLAGS删除、范围中expunge、租约失效、崩溃和磁盘满。
