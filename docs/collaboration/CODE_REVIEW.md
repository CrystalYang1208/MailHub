# 代码审查

审查者按以下条件判断，技术负责人承担最终架构与合并审核：

- Change范围、FR优先级、AC/CR一致；不存在阶段外业务扩展。
- Host只负责HTTP边界，Application端口隔离业务与适配器；对象归属从当前认证用户确定。
- API先合同、再生成类型、再实现与契约测试；新operationId不重复，错误中文可操作。
- DDL追加迁移而非ORM覆盖，事务/外键/UID幂等/全文索引同提交，迁移失败可恢复。
- Loopback/Host/Origin/随机进程令牌与会话校验完整，工程路由不能误当成生产认证。
- 凭据使用批准的用户解锁密钥封装及DPAPI方案；日志不含内容、完整地址、附件名或秘密。
- 锁定文件与版本一致，实际SQLite符合修复底线，漏洞查询失败不得报无漏洞。
- 测试针对行为及失败路径；模拟、合成、真实证据明确，原证据不覆盖。
- staged diff无私有数据，README与任务状态能让另一位开发者复现。

不要求重复阶段二已通过的真实邮箱互发和性能测试。只重跑受本次修改影响的检查；CI失败时先定位再修复，不绕过校验。合并后由技术负责人按接口整合计划联调，按Change验收结果归档。
